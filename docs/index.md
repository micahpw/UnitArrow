# UnitArrow

*Column-level unit metadata for Apache Arrow that survives the wire.*

A unit annotates a whole Arrow column as extension metadata, travels inside
IPC / Flight / Parquet with no sidecar files, and converts as a metadata-level
operation — never a per-element object.

!!! info "What this site is for"
    The **Live examples** section is generated by *running* `unitarrow-core`
    against the conformance registry. Every canonical string, factor, dimension
    vector, and error code shown there was produced by the implementation, not
    typed by hand — so nothing on those pages can drift from behaviour.

    That discipline is not decoration. This project has already found a spec
    formula that returned 416 °F for boiling water and a registry example that
    was not valid TOML. Documentation that executes cannot lie in those ways.

## The shape of the thing

=== "Canonical form"

    Input notation is flexible; canonical form is not. It exists to make
    equality and hashing identical across languages, so there is exactly one
    spelling per expression — and it contains no `/`, because every sign lives
    inside an exponent.

    ```text
    MW/h      →  MW*h^-1
    1/s       →  s^-1
    h*MW      →  MW*h
    W/K/m^2   →  W*K^-1*m^-2
    ```

=== "Exact factors"

    Conversion factors are exact rationals. Floating point appears only when a
    value is finally applied, which is what makes factors auditable and
    bit-identical across Rust, Python, and WASM.

    ```text
    MW*h → Btu    180000000000000000 / 52752792631
    32 degF → K   exactly 5463/20, i.e. 273.15
    ```

=== "The temperature trap"

    A 20-degree Celsius *difference* is 36 °F, not 68 °F. Absolute temperatures
    convert through offsets; differences must use the delta units, which carry
    none. Conflating them is the bug the affine/delta split exists to prevent.

    ```text
    degC       → degF        20 → 68
    delta_degC → delta_degF  20 → 36
    ```
